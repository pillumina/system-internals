# T2_03_1_调度策略工厂

`SchedulingPolicyFactory`（`motor/coordinator/scheduler/policy/factory.py:64`）是 Coordinator 数据面唯一的策略注册点。`Scheduler` 在构造时通过它拿到具体的策略对象（`motor/coordinator/scheduler/scheduler.py:74`），而新增策略只需 `register(NewSchedulerType, factory)`，不必修改 `Scheduler` 自身——这是 OCP（开闭原则）的体现。

## 类型与协议

`BaseSchedulingPolicy` 定义了所有策略必须实现的最小契约（`motor/coordinator/scheduler/policy/base.py`）：

```python
PolicyFactory = Callable[[InstanceProvider], BaseSchedulingPolicy]

def register(scheduler_type: SchedulerType, factory: PolicyFactory) -> None: ...
def create(scheduler_type: SchedulerType, instance_provider: InstanceProvider) -> BaseSchedulingPolicy: ...
```

注册表使用 dict 维护 `SchedulerType -> factory` 的映射（`factory.py:42`）。注册时序通过模块级副作用完成：

```python
# factory.py:73-78
def _register_builtin() -> None:
    register(SchedulerType.ROUND_ROBIN, _create_round_robin)
    register(SchedulerType.LOAD_BALANCE, _create_load_balance)
    register(SchedulerType.KV_CACHE_AFFINITY, _create_kv_cache_affinity)

_register_builtin()
```

`_create_round_robin`、`_create_load_balance`、`_create_kv_cache_affinity` 都是局部工厂，懒加载对应模块避免循环导入。

## 内置策略

| SchedulerType | 工厂 | 适用场景 |
|---------------|------|---------|
| `ROUND_ROBIN` | `_create_round_robin` | 实例同构、负载均衡要求低，调试或基准场景 |
| `LOAD_BALANCE` | `_create_load_balance` | 通用负载均衡，按 endpoint 实时 workload 打分 |
| `KV_CACHE_AFFINITY` | `_create_kv_cache_affinity` | prefill 流量大、prefix 重复多，希望最大化 KV 命中 |

详细行为见：
- `T2_03_2_KVCache亲和性调度.md`
- `T2_03_3_负载均衡策略.md`
- `T2_03_4_轮询策略.md`

## 选用哪一条

策略选择由 `CoordinatorConfig.scheduler_config.scheduler_type` 决定，Scheduler 在构造时读取：

```python
# scheduler.py:66-78
if isinstance(config, SchedulerType):
    self._policy_type = config
    self._config = None
else:
    self._policy_type = config.scheduler_config.scheduler_type
    self._config = config
self._instance_provider = instance_provider
self._scheduling_policy = SchedulingPolicyFactory.create(self._policy_type, self._instance_provider)
if self._config and hasattr(self._scheduling_policy, "set_endpoint_instance_score_weight"):
    self._scheduling_policy.set_endpoint_instance_score_weight(
        self._config.scheduler_config.endpoint_instance_score_weight
    )
```

注意：传 `SchedulerType` 直接当作 policy 类型时（如单元测试或单次构造），`_config` 为 None，跳过 score weight 注入。

## 选型影响半径

调度策略决定了"什么算好的实例"，但**不影响** Router 选 `UnifiedPDRouter` 还是 `PDHybridRouter`——那是 `select_router_class` 根据拓扑选出的，与策略正交。

策略与 workload 跟踪的耦合点在于 `update_workload`：

- `RoundRobinPolicy` 不实现 `update_workload`（继承默认实现），workload 永远为零，`Scheduler._allocate_selected` 选择 `Workload()`（`scheduler.py:162-166`），适合"调度策略不感知负载"的场景；
- `LoadBalancePolicy` 与 `KvCacheAffinityPolicy` 都会把 `update_workload` 委托给 `InstanceProvider.update_instance_workload`，让 InstanceManager 维护端点维度的 workload 计数器。

## 扩展示例：新增 PrefillPin 策略

假设需要新增一种"按 job_name 钉住 prefill"的策略，可以这样写：

```python
# motor/coordinator/scheduler/policy/prefill_pin.py
from motor.coordinator.scheduler.policy.base import BaseSchedulingPolicy
from motor.coordinator.domain import InstanceProvider

class PrefillPinPolicy(BaseSchedulingPolicy):
    def __init__(self, instance_provider):
        super().__init__(instance_provider=instance_provider)
        self._instance_provider = instance_provider

    def select_instance_and_endpoint_from_list(self, instances, role=None, req_info=None):
        target = (req_info.req_data.get("model") if req_info else None) or "default"
        for inst in instances:
            if inst.job_name == target:
                endpoint = inst.get_all_endpoints()[0] if inst.get_all_endpoints() else None
                return (inst, endpoint) if endpoint else None
        return None

# 在某处注册
from motor.coordinator.scheduler.policy import factory
from motor.config.coordinator import SchedulerType

def _create_prefill_pin(ip):
    from motor.coordinator.scheduler.policy.prefill_pin import PrefillPinPolicy
    return PrefillPinPolicy(instance_provider=ip)

factory.register(SchedulerType.PREFILL_PIN, _create_prefill_pin)
```

注册一次后，`SchedulerType.PREFILL_PIN` 即可作为 `scheduler_type` 的合法取值，无需改动 Scheduler 主类。

## 错误处理

`create` 在遇到未注册的 `SchedulerType` 时显式抛 `ValueError`，避免静默退化：

```python
# factory.py:58-61
factory = _REGISTRY.get(scheduler_type)
if factory is None:
    raise ValueError(f"Unsupported scheduling policy: {scheduler_type}")
return factory(instance_provider)
```

调用方（`Scheduler.__init__`）会把这个异常向上抛，由 Coordinator 启动流程捕获并使进程退出失败，保证线上不会"看似启动成功但其实是 NoOp 策略"。
