# T2_02_2_混合部署路由逻辑

`PDHybridRouter`（`motor/coordinator/router/strategies/pd_hybrid.py:38`）面向单实例推理：选一台 union（或 prefill-only fallback）实例一次性完成 prefill + decode。它是 PD 拓扑退化场景的兜底，也是 A5 D 实例虚推兼容的入口——通过 `select_router_class` 的"无 ROLE_D 时回退到 PDHybridRouter"分支触发（详见 `T2_02_Router路由策略.md`）。

## 候选角色解析

`_resolve_candidate_roles`（`pd_hybrid.py:53-71`）是 hybrid 的角色选择器：

```python
async def _resolve_candidate_roles(self) -> tuple[PDRole, ...]:
    if self._resolved_roles is not None:
        return self._resolved_roles
    roles = await self._scheduler.get_available_instance_roles()
    if PDRole.ROLE_U in roles:
        self._resolved_roles = (PDRole.ROLE_U,)
        return self._resolved_roles
    if PDRole.ROLE_P in roles:
        self.req_info.trace_obj.set_trace_error_message(
            "No union instances available, using prefill instances for single-node scheduling",
            is_meta=True,
        )
        self._resolved_roles = (PDRole.ROLE_P,)
        return self._resolved_roles
    self._resolved_roles = ()
    return self._resolved_roles
```

关键点：

1. 优先选 `ROLE_U`（典型 union 实例，引擎能同时跑 prefill 与 decode）；
2. 当仅有 `ROLE_P` 时退化到 prefill 实例，把"P/D 拓扑退化为 hybrid"的原因写入 meta trace，便于运维追溯；
3. 解析结果按请求维度缓存到 `self._resolved_roles`，避免每次重试都重新探测拓扑。

`_manage_hybrid_resource_context`（`pd_hybrid.py:86-98`）随后调用 `_manage_resource_context(role, self.release_all)`，在 yield 资源后由基类的 `_manage_resource_context` 完成 `(instance, endpoint, workload)` 三元组分配，再走 `_manage_client_context` 拿到 HTTP 客户端。

## 节点故障取消器

`_manage_canceller_context`（`pd_hybrid.py:107-131`）为本次 attempt 注册一个节点故障取消器：当 HTTPClientPool 探测到 endpoint 失效（典型场景：节点被踢出可用池），通过 `pool.register_canceller` 把当前 asyncio Task 与取消回调绑定，回调以 `NODE_FAULT` 原因触发 `task.cancel(msg=reason)`，让上层重试决策（`_stream_retry_allowed`/`_post_retry_allowed`）介入而不是等 transport 超时。

`_uncancel_current_task`（`pd_hybrid.py:133-138`）配合 `task.uncancel()` 清掉 pending cancel 状态，让下一次 attempt 能干净地进入调度。

## 流式处理路径

`_generate_stream`（`pd_hybrid.py:199-288`）结构清晰：

```python
async def _generate_stream(self, req_data: Dict[str, Any]) -> AsyncGenerator[str, None]:
    with self._trace_span("PDHybrid_Stream", True):
        await self.do_encode()                         # 多模态预热
        self.is_meta = False
        max_retry = max(self.config.exception_config.transport_retry_limit, 1)
        reschedule_enabled = self.config.exception_config.reschedule_enabled
        if reschedule_enabled:
            req_data["return_token_ids"] = True

        for attempt in range(max_retry):
            stream_adapter_state: Dict[str, Any] = {}
            if not self._stream_commit_controller.commit_sealed:
                self._stream_commit_controller.begin_attempt(attempt + 1)
            try:
                async with aclosing(
                    self._stream_inference_attempt(req_data, api, attempt, max_retry, stream_adapter_state)
                ) as attempt_stream:
                    async for chunk in attempt_stream:
                        yield chunk
                return
            except asyncio.CancelledError as e:
                reason, retryable = check_cancel_error(e)
                retry = retryable and attempt < max_retry - 1 \
                        and (not self._stream_body_sent or reschedule_enabled)
                if not retry:
                    if not retryable:
                        raise                                          # CLIENT_DISCONNECT/DISPATCH_ABORT 透传
                    self._uncancel_current_task()
                    self.req_info.update_state(ReqState.EXCEPTION)
                    raise RuntimeError(f"Cancelled because of {reason}")
                self._uncancel_current_task()
            except Exception as e:
                if isinstance(e, HTTPException):
                    transport_retryable = False
                elif isinstance(e, (UpstreamHTTPError, httpx.RequestError)):
                    transport_retryable = is_retryable_upstream_error(e)
                else:
                    transport_retryable = True
                retry = attempt < max_retry - 1 \
                        and (not self._stream_body_sent or reschedule_enabled) \
                        and transport_retryable
                if not retry:
                    self.req_info.update_state(ReqState.EXCEPTION)
                    raise

            wait_time = self.config.exception_config.retry_delay * (2 ** attempt)
            await asyncio.sleep(wait_time)
```

要点：

- 每个 attempt 用 `aclosing` 包住，保证 generator 退出时内部 chunk 流被关闭；
- `check_cancel_error`（`base.py:80-91`）把 cancel 原因分为 `CLIENT_DISCONNECT`/`DISPATCH_ABORT`（不可重试）、`NODE_FAULT`（可重试）、其他；
- 重试条件额外要求 `_stream_body_sent` 为 False，或 `reschedule_enabled=True`——一旦已经向客户端 commit 了字节，没有重试计划就不能重新尝试；
- 重试间隔 `retry_delay * 2^attempt` 是指数退避；
- `req_info.update_state(ReqState.EXCEPTION)` 在放弃时显式标记状态，便于观测面统计。

`_stream_inference_attempt`（`pd_hybrid.py:169-197`）在 `_inference_lifecycle`（`pd_hybrid.py:140-152`）内部组合 `_inference_span`（trace）、`_manage_request_context`、`_manage_hybrid_resource_context`、`_manage_client_context`、`_manage_canceller_context`，再调 `forward_stream_request` 拉数据。当 `reschedule_enabled=True` 时，chunk 会先经过 `Rescheduler.process_stream_chunk`（`pd_hybrid.py:187-194`）累加 token id 缓存，供下一 attempt 续跑。

## 非流式处理路径

`_generate_post`（`pd_hybrid.py:290-363`）结构与流式几乎对称，但有两点差异：

1. 不需要 `StreamCommitController`，直接 `_inference_lifecycle` 拿 client，调用 `forward_request(api, req_data, client, infer_timeout)`；
2. 拿到响应后若 `effective_entry_api()` 含 `chat` 且 body 的 `object == "text_completion"`，调用 `adapt_completion_nonstream_to_chat`（`pd_hybrid.py:313-314`）把旧式 completions 转成 chat 形状；
3. `adapters.strip_nonstream_response_body_for_client` 剥离仅对内部用的字段（如 logprobs）。

## 实例标签

`_instance_label`（`pd_hybrid.py:100-105`）返回 `U=[ip job_name]` 形式的标签，让日志中 P/D/Unified 三种路由的格式保持一致，方便 grep `U=[` 与 `P=[` `D=[` 做对比分析。

## 与 UnifiedPDRouter 的关键区别

| 维度 | UnifiedPDRouter | PDHybridRouter |
|------|-----------------|----------------|
| 拓扑 | 需要兼容的 P+D | U（或仅 P 退化） |
| commit barrier | prefill + decode 双 ready | 仅 engine ready（hybrid 单 leg） |
| 角色解析 | `_create_attempt` 中两段 `select_and_allocate` | `_resolve_candidate_roles` 一次性选 role |
| dispatch envelope | 必须写 `MOTOR_DISPATCH_KEY` 区分 P/D leg | 不需要（单 leg），但仍可能由引擎侧 envelope 标记 role |
| reschedule 续跑 | 通过 `_active_retry_plan` 调整 prompt | 通过 `Rescheduler.prepare_retry_request` 调整 req_data |
