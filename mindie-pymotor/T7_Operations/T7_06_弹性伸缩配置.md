# 弹性伸缩配置

## 弹性伸缩概述

Motor 的弹性伸缩包含两个维度：**水平扩展**（增减 PD 实例数量）和**角色再分配**（调整 P/D 实例比例）。ScaleP2D（Scale Prefill to Decode）是 Motor 在 PD 分离场景下实现角色级别弹性伸缩的核心机制：当 D 实例因硬件故障不可用时，通过停止部分 P 实例来释放节点资源，为 D 实例的恢复或替换腾出容量。

弹性伸缩的完整配置涉及三个层面：Controller 侧 JSON 配置、NodeManager 侧参数配置、以及 K8s CRD 层面的资源配额配置。

## Controller 侧核心配置

### 故障容忍总开关

```json
{
  "fault_tolerance_config": {
    "enable_fault_tolerance": true
  }
}
```

`enable_fault_tolerance` 必须为 `true` 才能启用 FaultManager。FaultManager 关闭时，Controller 仅被动接收心跳，不会主动执行任何自愈动作。

### ScaleP2D 专项配置

```json
{
  "fault_tolerance_config": {
    "enable_fault_tolerance": true,
    "enable_scale_p2d": true,
    "scale_p2d_d_instance_reinit_wait_timeout": 60,
    "strategy_center_check_interval": 1
  }
}
```

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `enable_scale_p2d` | bool | `false` | 是否启用 ScaleP2D |
| `scale_p2d_d_instance_reinit_wait_timeout` | int | 60 | D 实例自恢复等待超时（秒） |
| `strategy_center_check_interval` | int | 1 | 策略中心轮询间隔（秒） |

`scale_p2d_d_instance_reinit_wait_timeout` 是最关键的调参项。在 D 实例故障后，Controller 会在这个时间窗口内等待 D 实例自恢复（重新初始化并上报心跳）。如果 D 实例在超时前恢复到 INITIAL 或 ACTIVE 状态，ScaleP2D 流程取消，不会停止任何 P 实例。超时后若 D 仍处于 INACTIVE 等可抢占状态，才会继续后续的 P 实例选择流程。

**调参建议**：
- 如果 D 实例的重初始化时间较长（如加载大模型耗时），将此值设为 120 秒或更高。
- 如果故障场景下 D 实例无法自恢复（需要人工替换节点），可以设为一个较小值以加快 P 资源释放。
- 此参数的单位是秒，与 `strategy_center_check_interval` 无直接数学关系。

### 实例隔离配置

```json
{
  "fault_tolerance_config": {
    "active_timeout": 10,
    "inactive_timeout": 30
  }
}
```

| 配置项 | 说明 |
|--------|------|
| `active_timeout` | ACTIVE 实例心跳超时阈值（秒），超时后转为 INACTIVE |
| `inactive_timeout` | INACTIVE 实例在被删除前的最大等待时间（秒） |

## NodeManager 侧配置

### 心跳相关

```yaml
# NodeManager 配置中
heartbeat_interval: 3      # 心跳发送间隔（秒）
heartbeat_timeout: 10     # Controller 侧心跳超时阈值
```

NodeManager 侧的心跳间隔需要与 Controller 侧的 `active_timeout` 配合。建议心跳间隔 < 超时阈值的 1/3，为网络抖动预留缓冲空间。

### 实例规格配置

```yaml
# examples/deployer/yaml_template/engine_template.yaml
resources:
  gpu: "1"
  memory: "32Gi"
  cpu: "8"
```

`engine_template.yaml` 控制每个 PD 实例的规格，影响调度时的资源分配决策。P 实例和 D 实例通常需要不同配置：P 实例偏计算，建议更多 GPU 资源；D 实例偏显存，建议更大显存配额。

## K8s CRD 层面的优先级调度

在 CRD 部署模式下（详见 T7_02），ScaleP2D 需要 K8s CRD 支持**优先级调度**和**实例强制删除**能力。这通过 `InferServiceSet` CRD 的 `priority` 字段配置：

```yaml
# examples/deployer/yaml_template/infer_service_template.yaml
spec:
  priority: 100  # 值越高优先级越高
```

优先级用于在资源紧张时决定先抢占哪些实例。ScaleP2D 停止 P 实例后，由 CRD Controller 强制回收 Pod 并释放节点，供故障 D 实例恢复使用。

## 调度策略选择

弹性伸缩的效果也与调度策略选择密切相关（详见 T2_03）：

- **KvCacheAffinityPolicy**：适合多轮对话、高前缀重复率场景。在实例数动态变化时，亲和性调度能更高效地利用已有 KV-Cache。
- **LoadBalancePolicy**：适合请求规模差异大、实例规格一致的场景，能更均匀地分散负载。
- **RoundRobinPolicy**：调试和测试场景优先，不建议作为生产默认策略。

## 调参检查清单

在生产环境部署或调整弹性伸缩参数前，建议按以下清单逐项确认：

1. `enable_fault_tolerance: true` — 整个故障容忍体系的总开关。
2. `enable_scale_p2d: true` — 在 PD 分离且 D 实例硬件故障风险较高的场景下建议开启。
3. `scale_p2d_d_instance_reinit_wait_timeout` — 根据 D 实例启动时间调整，默认 60 秒，较大模型建议 120 秒以上。
4. 心跳相关参数（`heartbeat_interval`、`active_timeout`）— 确保比例关系合理（间隔 < 1/3 超时阈值）。
5. CRD 侧的 `priority` 配置 — 确保 P 实例优先级低于 D 实例，使 ScaleP2D 能够成功抢占 P 资源。
6. `forced_separated_instances` 策略 — 确认故障后是否需要运维手动恢复，避免自动恢复导致故障实例盲目重新加入服务池。
