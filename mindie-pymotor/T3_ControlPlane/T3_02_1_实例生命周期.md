# T3_02_1_实例生命周期

PD 实例在 Controller 中以 `InsStatus` 状态机驱动，每个状态的进入/退出都有明确的触发条件与对应的副作用（Observer 通知、ETCD 持久化、Conductor 注册）。本文基于 `motor/controller/core/instance_manager.py` 的转换表与状态处理器梳理完整生命周期。

## 状态枚举

`InsStatus`（`motor/common/resources/instance.py`）定义五种状态：

```python
class InsStatus(str, Enum):
    INITIAL  = "initial"    # 实例刚被 Controller 装配，未握手
    INACTIVE = "inactive"   # 实例已停止或不可用
    ACTIVE   = "active"     # 实例正常提供服务
    PAUSED   = "paused"     # 实例被手动暂停（滚动更新等）
    DELETED  = "deleted"    # 终态，从实例池移除
```

`InsConditionEvent`（同模块）定义触发事件：`INSTANCE_INIT`、`INSTANCE_NORMAL`、`INSTANCE_ABNORMAL`、`INSTANCE_HEARTBEAT_TIMEOUT`、`INSTANCE_PAUSED`、`INSTANCE_RESUMED`。

## 转换表全景

`instance_manager.py:105-125`：

| From \ Event | INIT | NORMAL | ABNORMAL | HEARTBEAT_TIMEOUT | PAUSED |
|--------------|------|--------|----------|-------------------|--------|
| INITIAL      | INITIAL | ACTIVE | INACTIVE | DELETED | PAUSED |
| ACTIVE       | -    | ACTIVE | INACTIVE | INACTIVE | PAUSED |
| INACTIVE     | INITIAL | ACTIVE | INACTIVE | DELETED | PAUSED |
| PAUSED       | -    | ACTIVE | INACTIVE | DELETED | PAUSED |

`RESUMED` 仅作用于 PAUSED → ACTIVE，未列入上面的二维表。

## 触发条件

`_handle_state_transition`（`instance_manager.py:777-808`）按以下顺序推断事件：

1. `event_override` 显式传入（典型用于 `_instances_management_loop` 主动传 `INSTANCE_HEARTBEAT_TIMEOUT`）；
2. `instance.is_all_endpoints_paused()` → `INSTANCE_PAUSED`；
3. `instance.is_all_endpoints_ready()` → `INSTANCE_NORMAL`；
4. `instance.is_have_one_endpoint_abnormal()` → `INSTANCE_ABNORMAL`；
5. `instance.is_any_endpoint_paused()` → `INSTANCE_PAUSED`（防止 INACTIVE → INITIAL 时 PreStop PAUSED 覆盖 ABNORMAL）；
6. 否则 → `INSTANCE_INIT`。

之后查 `transitions` 表得到 `to_state`，调用对应的状态处理器。

## 状态处理器

### `_handle_initial`（`instance_manager.py:619-627`）

仅在 `from_state != INITIAL` 且 `event == INSTANCE_INIT` 时回退到 INITIAL——这覆盖了"实例被标记 INACTIVE 后又收到 init 心跳"的边界情况。其他情况下保持 INITIAL 不动。

### `_handle_active`（`instance_manager.py:629-640`）

`from_state != ACTIVE` 且事件是 `NORMAL` 或 `RESUMED` 时切到 ACTIVE；事件类型决定 Observer 通知：

- `RESUMED` → `ObserverEvent.INSTANCE_RESUMED`；
- `NORMAL` → `ObserverEvent.INSTANCE_READY`；
- 同时调 `_report_inst_alarm(True)` 与 `_report_coordinator_alarm(True)` 清除异常告警。

### `_handle_inactive`（`instance_manager.py:642-674`）

`ABNORMAL`：直接置 INACTIVE，notify `INSTANCE_SEPERATED`。

`HEARTBEAT_TIMEOUT`：先调 `_check_node_managers_status(instance)`（`instance_manager.py:713-763`）主动查一遍 node manager 状态。若任一 node manager 报 endpoint 异常，置 INACTIVE 并 notify；若全部正常，则**不置 INACTIVE** 而是把所有 endpoint 的 `hb_timestamp` 刷成 `time.time()`，避免下一轮超时——这是为了规避 active-standby 模式下原主节点被 reboot 后 kubelet 无法上报 readiness、heartbeat 误超时的问题（注释 `instance_manager.py:653-662` 详述）。

### `_handle_paused`（`instance_manager.py:676-681`）

仅在事件是 `INSTANCE_PAUSED` 且状态非 PAUSED 时切到 PAUSED，notify `INSTANCE_PAUSED`，并通过 `_report_inst_alarm(instance)` 上报告警（无 cleared 参数 = 不清除）。

### `_handle_deleted`（`instance_manager.py:765-775`）

仅当 `event in (INSTANCE_HEARTBEAT_TIMEOUT, INSTANCE_ABNORMAL)` 且当前非 DELETED 时切到 DELETED，notify `INSTANCE_REMOVED`，然后调用 `del_instance(instance.id)` 从内存中删除。

## 副作用：Observer 通知

`_handle_state_transition` 在调用 `state_handler` 后并不直接 notify，而是各 handler 内部调 `self.notify(instance, ObserverEvent.XXX)`。`notify`（`instance_manager.py:188-191`）把 Instance 包成 `ReadOnlyInstance` 后广播给所有 Observer：

```python
def notify(self, instance: Instance, event: ObserverEvent) -> None:
    readonly_instance = ReadOnlyInstance(instance)
    for observer in self.observers:
        observer.update(readonly_instance, event)
```

Observer 不允许修改 instance（`ReadOnlyInstance` 是不可变视图），保证状态机修改权只在 InstanceManager 内。

## 副作用：ETCD 持久化

`_handle_state_transition` 在状态真正变化（`from_state != instance.status`）且 `enable_etcd_persistence=True` 时调 `self.persist_data()`。`persist_data`（`instance_manager.py:193-233`）生成新 version + checksum 后异步写盘，写完才把 `_data_version` 推进一步。

## 副作用：告警上报

`_handle_active` 与 `_handle_inactive` 调用 `_report_inst_alarm`/`_report_coordinator_alarm`（`instance_manager.py:683-711`）通过 `Observability().add_alarm` 上报：

- `InstanceExceptionAlarm.INSTANCE_EXCEPTION`：任一实例异常时上报；
- `CoordinatorExceptionAlarm.INSTANCE_MISSING`：当某 role（prefill/decode）没有 ACTIVE 实例时上报；当 role 重新可用时上报 `Cleared.YES` 自动清除。

## 强分离生命周期

`separate_instance`（`instance_manager.py:426-472`）与 `recover_instance`（`instance_manager.py:486-524`）形成完整的"运维隔离—恢复"闭环：

1. `separate_instance(id)`：把 id 加入 `forced_separated_instances`；若当前是 ACTIVE，降级到 INACTIVE 并 notify `INSTANCE_SEPERATED`；
2. 实例不会因为心跳自动恢复：`_handle_state_transition` 检测 `instance.id in forced_separated_instances and to_state == ACTIVE` 时直接 `return True`（success）但跳过状态转移（`instance_manager.py:817-823`）；
3. `recover_instance(id)`：从集合中移除；若同 `job_name` 已有更高 id 的实例，只清理旧实例的强分离标记（防误恢复）；
4. 实例转移 DELETED 时自动从 `forced_separated_instances` 移除（`instance_manager.py:847-855`）。

## 后台线程驱动

`_instances_management_loop`（`instance_manager.py:599-617`）以 `instance_manager_check_interval` 秒为周期扫描所有非 DELETED 实例，对 `is_all_endpoints_alive()=False` 的实例显式触发 `_handle_state_transition(instance, InsConditionEvent.INSTANCE_HEARTBEAT_TIMEOUT)`。这是心跳场景之外的"心跳超时自检"，保证即使 NodeManager 心跳链路断了 Controller 也能在有限时间内把异常实例降级或删除。

## 生命周期全景

```
                       ┌──────────────┐
                       │  (尚未注册)   │
                       └──────┬───────┘
                              │ add_instance()
                              ▼
   ┌──────────────────────────────────────────────────────────────┐
   │ INITIAL ───心跳正常────► ACTIVE ◄─── 心跳正常 ────┐         │
   │    │                     │  │                    │         │
   │    │ PreStop/ABNORMAL    │  │ RESUMED            │         │
   │    ▼                     │  ▼                    │         │
   │ INACTIVE ◄──心跳超时─────┤  PAUSED ──── 手动恢复 ┘         │
   │    │                     │                                       │
   │    │ 连续超时/强制分离    │                                       │
   │    ▼                     │                                       │
   │ DELETED ◄──心跳超时──────┘                                       │
   └──────────────────────────────────────────────────────────────┘
```

任意状态在 `enable_etcd_persistence=True` 时都会通过 `persist_data` 持久化；任意状态转移都会触发对应的 Observer 通知与告警上报。Controller 重启后从 ETCD 恢复并主动推一次 `EventType.SET` 让 Coordinator 重新同步，避免状态漂移。
