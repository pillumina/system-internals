# T4_01 故障分类体系

## 概述

故障分类体系是整个 MindIE-PyMotor 容错机制的语义基础，它把硬件驱动、固件、K8s 集群、推理引擎上报的原始事件归一化为一组有限、可枚举、可路由的内部表示。所有的故障感知、等级评估、策略分发动作都建立在这套分类之上。该体系集中定义在 `motor/controller/fault_tolerance/fault_types.py`，与 `motor/common/alarm/` 下的告警事件枚举相互配合使用。

## 分类维度

故障从三个正交维度刻画：

- **类别（FaultCategory）**：硬件故障（`HARDWARE`）与软件故障（`SOFTWARE`）的二分，决定 `FaultInfo` 中字段的填充策略（参见 `motor/controller/fault_tolerance/fault_types.py:26-30`）。
- **级别（FaultLevel / OriginFaultLevel）**：0 到 6 共七级，决定是否触发自动恢复动作，参见 `motor/controller/fault_tolerance/fault_types.py:65-78`。
- **类型（HardwareFaultType）**：在硬件故障下进一步细分，区分卡故障、卡间网络故障和节点级故障，参见 `motor/controller/fault_tolerance/fault_types.py:44-49`。

## 故障级别映射

OriginFaultLevel（来自驱动/固件字符串）与 FaultLevel（控制面内部表示）的映射定义在 `motor/controller/fault_tolerance/fault_types.py:196-205`：

| FaultLevel | OriginFaultLevel | 含义 |
|------------|------------------|------|
| `L1` | `NotHandleFault`, `SubHealthFault` | 仅上报，不处理 |
| `L2` | `RestartRequest` | 自愈或预隔离，触发 token 重推 |
| `L3` | `RestartBusiness` | 无法自动处理 |
| `L4` | `FreeRestartNPU` | 隔离并触发恢复策略（缩 P 保 D） |
| `L5` | `RestartNPU` | NPU 重启 |
| `L6` | `SeparateNPU`, `PreSeparateNPU` | NPU 分离 / 节点重启 |

软件故障的级别映射见 `_map_engine_status_to_fault_level`（`motor/controller/fault_tolerance/fault_types.py:128-135`）：`EngineStatusType.DEAD`（1）和 `UNHEALTHY`（2）均映射为 `L2`，而具体策略由 `fault_code`（`SpecialFaultCode.ENGINE_DEAD=0x1000001` / `ENGINE_UNHEALTHY=0x1000002`）在策略中心二次区分（`motor/controller/fault_tolerance/fault_types.py:33-37, 137-144`）。

## FaultInfo 数据模型

`FaultInfo` 是统一承载两类故障的对象，定义在 `motor/controller/fault_tolerance/fault_types.py:81-103`：

- **硬件字段**：`fault_type`（`HardwareFaultType`）、`npu_name`、`origin_fault_level`。
- **软件字段**：`exception_type`、`exception_message`、`engine_id`、`engine_status`、`timestamp`、`additional_info`。

硬件 `FaultInfo` 由 `configmap_parser` 直接构造（`motor/controller/fault_tolerance/k8s/configmap_parser.py:106-126, 270-287`），软件 `FaultInfo` 通过 `FaultInfo.from_exception()` 工厂方法生成（`motor/controller/fault_tolerance/fault_types.py:104-126`）。

## NodeMetadata 与 InstanceMetadata

节点和实例的故障状态通过 `NodeMetadata`（`motor/controller/fault_tolerance/fault_types.py:210-236`）和 `InstanceMetadata`（`motor/controller/fault_tolerance/fault_types.py:239-273`）承载。`NodeMetadata.hardware_fault_infos` 与 `software_fault_infos` 是以 `fault_code` 为键的字典，方便去重和后续等级聚合。`InstanceMetadata.strategy_fault_level` 用于记录"当前正在运行的策略对应的故障级别"，避免策略被同级别抖动反复启停。

## PreSeparateNPU 的特殊处理

`PreSeparateNPU` 静态映射到 `L6`，但运行时会按节点上是否存在活跃实例动态降级：当节点仍有 `INITIAL/ACTIVE` 实例时降为 `L2`，否则保持 `L6`。该逻辑位于 `motor/controller/fault_tolerance/fault_manager.py:367-419`（`_refresh_instance_fault_level` 中的两阶段重评），用于在实例尚未撤离前避免误隔离。

## 告警事件类型

`motor/common/alarm/` 下的事件枚举与故障分类一一对应：

- `ScaleP2DEvent`：缩 P 保 D 触发事件，含被停 Prefill 实例 ID 列表（见 `motor/controller/fault_tolerance/strategy/scale_p2d.py:163-184`）。
- `PrecisionIssueAlarm`：推理精度异常告警，由 Coordinator 侧 ChatProbe 触发（`motor/coordinator/fault_tolerance/alarm/precision_alarm.py:36-74`）。
- `ClusterConnectionAlarm`、`ServerExceptionAlarm`：集群连接与服务器异常的告警事件。

这些事件最终由 `Observability.add_alarm` 持久化与上报，详见 T4_05_PrecisionAlarm 与 T8_DeepDives 中的告警体系章节。
