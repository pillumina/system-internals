# T1_02 PD 分离原理

PD 分离（Prefill/Decode Disaggregation）的核心思想是把一次推理请求的两个阶段分别调度到不同实例上完成，二者通过 KV Cache 传输协同。本节给出 PDRole 的四种取值、P/D 协同的语义以及 KV 传输的衔接方式，并说明哪些场景适合部署 PD 分离。PD 分离的完整用户视角描述见 `docs/zh/user_guide/features/pd_disaggregation.md`，设计细节见 `docs/zh/design/pd_disaggregation.md`。

## PDRole 四种角色

PDRole 枚举在 `motor/common/resources/instance.py:L41-L55` 定义：

```
class PDRole(str, Enum):
    ROLE_E = "encode"
    ROLE_P = "prefill"
    ROLE_D = "decode"
    ROLE_U = "union"
```

四种角色对应不同的协同位置：

- `ROLE_E = "encode"`（Encode）：多模态场景下的预处理实例，负责把图像/视频等非文本输入编码成 token 与 KV。它和 `ROLE_P` 必须配套出现（`REQUIRED_MET_EPD` 才视为就绪），但并不出现在每条推理路径上——只有当请求携带多模态消息时才走 Encode 阶段。
- `ROLE_P = "prefill"`（Prefill）：执行预填充的实例，一次性把 prompt 跑完并产出 KV Cache。
- `ROLE_D = "decode"`（Decode）：执行自回归解码的实例，需要拿到 Prefill 的 KV Cache 才能继续生成。
- `ROLE_U = "union"`（Union）：单实例同时承担 Prefill 与 Decode（即 PD 混部 / hybrid 模式），用于节点资源受限或 PD 降级场景。历史上 `ROLE_U` 还接受字面量 `"both"` 与 `"hybrid"`（见 `_missing_` 实现），保留向后兼容。

`ROLE_U` 的存在让 PD 分离可以在节点级别回退——当只剩 Prefill 实例可用时，Coordinator 会把请求路由到 Prefill 实例并要求它独立完成 Prefill+Decode，具体逻辑见 `motor/coordinator/router/strategies/pd_hybrid.py:L53-L71` 的 `_resolve_candidate_roles`。

## KV Cache 传输：协同的衔接

Prefill 与 Decode 不在同一进程，必须把 Prefill 写出的 KV Cache 搬到 Decode 实例的 HBM 里，Decode 才能继续生成。这一步在 MindIE PyMotor 中是通过引擎 Connector 完成的，框架并不直接搬运 KV，而是依据 Connector 上报的 `dispatch_capabilities` 选择执行计划：

- `concurrent_engine_sync`：P 与 D 并发执行，由引擎自行同步 KV（典型如 `MooncakeLayerwiseConnector`，每生成一层就把当前层 KV 同步到 D）。
- `prefill_handoff_decode`：Prefill 完成后整体把 KV 交给 Decode（典型如 `MooncakeConnectorV1`）。

具体的 connector 识别白名单与执行计划推导在 `docs/zh/design/pd_disaggregation.md` 里有详细表格；其中 `MultiConnector` 只看 `connectors[0]`（传输层），KV 池/存储类连接器作为后端不参与判定。Coordinator 只在 P/D 两端共同支持的 capability 中挑选，且当没有共同 capability 时会 fail-closed 返回 503，避免把不兼容的 P/D 配在一起直到 KV 传输阶段才失败。

## 适用场景

PD 分离不是「越大越好」的银弹，下列场景收益最明显：

- **高并发、低延迟敏感**：Prefill 与 Decode 各自的 batch 独立调度，避免互相排队——典型如交互式问答、长 prompt 多轮对话。
- **Prefill 与 Decode 工作负载不对称**：例如 batch 中以短 prompt 居多但 Decode 长尾较长时，分离后 Prefill 实例可以做大 batch，Decode 实例专注增量生成。
- **多模态推理**：需要 Encode 预处理（`ROLE_E`），与 Prefill/Decode 串成三段流水线，各阶段可以独立扩缩容。

不适合 PD 分离的典型场景：

- **单实例、单 NPU 的极小部署**：协同成本（KV 传输、调度握手）超过收益，应该用 `ROLE_U`（Union / PD 混部）模式。
- **请求量极小**：Prefill/Decode 任一端长期空载，硬件利用率反而下降。

PD 分离的具体调度执行与 Router 选择策略见 `T1_03_整体架构.md` 和 `T2_03_Scheduler调度器`，Connector 识别与执行计划推导的完整描述见 `docs/zh/design/pd_disaggregation.md`。
