# T1_05 关键概念一览

本节给出贯穿 MindIE PyMotor 源码的关键概念定义与相互关系，便于在阅读后续章节时快速定位「这个名词到底对应哪个数据结构」。所有定义都基于源码（标注文件路径 + 行号），不再做语义延伸。

## PDRole

`motor/common/resources/instance.py:L41-L55`：

```
class PDRole(str, Enum):
    ROLE_E = "encode"
    ROLE_P = "prefill"
    ROLE_D = "decode"
    ROLE_U = "union"
```

PDRole 是实例的身份标签，四种取值的语义与协同位置见 `T1_02_PD分离原理` 与 `T8_01_PDRole状态语义`。`Instance.role` 字段（`motor/common/resources/instance.py:L151`）在 Controller 组装实例时被填入，并在 Coordinator 侧用于 `InstanceReadiness` 判断——见 `motor/coordinator/domain/scheduling.py:L56-L89` 的 `readiness_from_instances`。

## Instance

`motor/common/resources/instance.py:L138-L211`：`Instance` 是「一组 endpoint + 一份并行配置 + 一个角色」的逻辑实例，是集群中最核心的资源抽象。它的关键字段：

- `id`：Controller 分配的全局唯一 ID。
- `role`：PDRole 字符串。
- `parallel_config`：并行配置（dp/tp/pp/ep/world_size），见 `ParallelConfig`（同文件 L77-L135）。
- `node_managers`：组成该实例的 NodeManager 列表。
- `endpoints`：按 `pod_ip` 分组的 endpoint 字典，是 Instance 的核心索引结构。
- `gathered_workload`：聚合后的 workload 视图。

`Instance` 还提供状态查询与心跳更新接口（`is_endpoints_enough`、`is_all_endpoints_alive`、`update_heartbeat`、`get_all_endpoints` 等），并通过 `ReadOnlyInstance`（同文件 L503-L577）提供观察者模式下的只读视图。

## Endpoint

`Endpoint` 是实例内部的「单个推理服务端口」——通常对应 EngineServer 上的一个 OpenAI 兼容 HTTP 服务。它挂载在 `Instance.endpoints[pod_ip][endpoint_id]` 这棵二级字典上，携带 IP、端口、状态（`EndpointStatus`）以及 workload（`Workload`）。`Instance.get_all_endpoints()`（同文件 L428-L464）是扁平化访问入口，内部用版本号缓存避免重复构造 tuple。

## Workload

`Workload` 是 Endpoint 上的负载指标，最关键的两个字段是 `active_tokens`（当前在处理的 token 数）与 `active_kv_cache`（当前 KV Cache 占用）。`active_tokens` 用于调度选实例（避免把请求路由到饱和实例），`active_kv_cache` 用于 KV 亲和调度时的容量评估。

`Workload` 在调度链路里有三个语义动作，对应 `WorkloadAction` 枚举：`ALLOCATION`（分配时占用）、`RELEASE_TOKENS`（请求结束时释放 token）、`RELEASE_KV`（请求结束时释放 KV）。具体动作处理见 `motor/coordinator/router/workload.py` 的 `WorkloadActionHandler`。

## RequestInfo

`motor/coordinator/models/request.py` 中的 `RequestInfo` 是请求级别的状态对象，从 Endpoint 接收请求时构造，到请求结束（无论成功或失败）由 `RequestManager.del_req_info` 清理（`motor/coordinator/router/strategies/base.py:L211-L222`）。它的关键字段：

- `req_id` / `req_data`：请求 ID 与原始请求体。
- `state`：请求状态机（`ReqState` 枚举），从 ARRIVE → P/D_SCHEDULING → P/D_ALLOCATED → FIRST_TOKEN_FINISH → PREFILL_END → DECODE_END 或 EXCEPTION。
- `trace_obj`：分布式追踪对象（`TraceObj`，见 `motor/coordinator/tracer/tracing.py:L176-L313`）。
- `kv_affinity_debug`：KV 亲和调试信息（仅在 `kv_cache_affinity` 策略下填充）。
- `scheduling_constraint`：请求级调度约束（如指定 instance id）。

## InstanceReadiness

`motor/coordinator/domain/scheduling.py:L32-L89` 定义的 `InstanceReadiness` 是「当前可用实例能否支撑某部署形态」的判断结果：

```
REQUIRED_MET_EPD, ENCODE_PREFILL, REQUIRED_MET,
ONLY_PREFILL, ONLY_DECODE, ONLY_ENCODE, NONE, UNKNOWN
```

`readiness_from_instances(instances)` 根据当前可用实例的角色组合与 P/D connector capability 兼容性计算出 readiness；`BaseRouter` 在每次请求入口先调用 `scheduler.has_required_instances()` 拿到 readiness，决定是否进入路由（见 `BaseRouter._check_can_encode` 与 `UnifiedPDRouter._create_attempt`）。

## SchedulingFacade

`motor/coordinator/domain/scheduling.py:L116-L158`：`SchedulingFacade` 是 Router 与 Scheduler 之间的协议抽象（Protocol）。具体实现有两类：

- **in-process Scheduler**：单进程模式下 Router 直接调用同一进程内的 Scheduler。
- **AsyncSchedulerClient**：Scheduler 独立成进程时 Router 通过 ZMQ 客户端访问远端 Scheduler。

Router 只依赖 `SchedulingFacade` 的接口（`select_and_allocate` / `update_workload` / `has_required_instances` 等），不依赖具体实现——这是 PyMotor 能在「单进程 / 多 worker / Scheduler 独立进程」三种模式下共享同一 Router 代码的关键。

## SchedulerType

`motor/config/coordinator.py:L102-L114`：

```
class SchedulerType(Enum):
    LOAD_BALANCE = "load_balance"
    ROUND_ROBIN = "round_robin"
    KV_CACHE_AFFINITY = "kv_cache_affinity"
```

`SchedulerType` 决定 Coordinator 的负载均衡策略：

- `LOAD_BALANCE`：按 workload 选最小实例/endpoint（默认）。
- `ROUND_ROBIN`：轮询分配。
- `KV_CACHE_AFFINITY`：用 Mooncake Conductor 查询 prefix cache 命中度，结合负载打分——见 `motor/coordinator/scheduler/policy/kv_cache_affinity.py` 与 `docs/zh/user_guide/features/KV_cache_affinity.md`。

## CoordinatorConfig

`motor/config/coordinator.py:L348-L820` 是 Coordinator 的全局配置，包含：

- **调度**：`SchedulerConfig`（scheduler_type + 各种 kv_affinity 调参 + endpoint_instance_score_weight）。
- **异常处理**：`ExceptionConfig`（max_retry、transport_retry_limit、first_token_timeout、infer_timeout、reschedule_enabled 等）。
- **采样与探针**：`TokenSamplingConfig`（precision_check_enabled 等）。
- **追踪**：`TracerConfig`（endpoint、sampling rate 等）。
- **API/TLS/Rate Limit/Standby**：分别为 `ApiConfig` / `TLSConfig` / `RateLimitConfig` / `StandbyConfig`。
- **KV 事件**：`PrefillKvEventConfig`（conductor_service、block_size、endpoint 等）。

`CoordinatorConfig.from_json`（L384-L532）从 JSON 文件加载配置并做严格校验；`reload()`（L700-L707）支持热重载。
